# Roadmap — Магазин мороженого «Глейси»

Учебно-боевой проект, который станет реальным инструментом продажи
мороженого собственного производства. Клиент выбирает товар, оформляет
заказ без регистрации, оплачивает — владелец получает уведомление
и обрабатывает заказ в админке.

Ключевые принципы:

- **Простота** — гостевая покупка в один клик.
- **Гибкость** — производство под заказ (без остатков и резервов).
- **Расширяемость** — новый тип товара = клон проекта с новой БД.
- **AI-friendly** — структурированные данные для поисковых агентов.
- **Передаваемость** — админка понятна человеку без технического бэкграунда.

План условный — конкретные решения принимаются при реализации шагов.

## Стек

| Компонент | Решение | Почему |
|-----------|---------|--------|
| Фреймворк | Next.js 16 (App Router) | Отработан в kurstata, удобный деплой |
| Язык | TypeScript (strict) | Безопасность, проверено |
| Стили | CSS-модули + глобальные переменные (`:root`) | Контроль, без Tailwind |
| БД | Turso (libSQL) + Drizzle ORM | Отработано, бесплатно, просто |
| Корзина | Upstash Redis | Быстро, TTL, бесплатно |
| Очереди | Upstash QStash | Для фона (письма, PDF) |
| Аутентификация | Auth.js (JWT в httpOnly-куках) | Проверено в kurstata |
| Платежи | ЮKassa | Вебхук, песочница |
| Почта | Resend | Бесплатно 100 писем/день |
| PDF | @react-pdf/renderer | Генерация накладных |
| Хранилище (PDF) | Cloudflare R2 | Бесплатно, S3-совместимо |
| Хранилище (картинки) | Vercel Blob | Интеграция с Next.js |
| Деплой | Vercel | Автоматически при пуше |

## Этапы

### Этап 0: Подготовка и дизайн-система

- Создать Next.js 16 проект.
- Настроить `globals.css` — вынести все параметры из макета в `:root`
  (цвета, шрифты, отступы, радиусы).
- Настроить окружение (.env, подключения к Turso, Redis, R2, Resend,
  Auth.js, Vercel Blob).

### Этап 1: Перенос и декомпозиция вёрстки

- Перенести старые HTML-страницы (главная, каталог) в Next.js как статичные.
- Разбить на компоненты (Header, Footer, ProductCard, Button, Container).
- Стили — CSS-модули с заменой хардкода на переменные из `:root`.
- Сделать роутинг: `/`, `/catalog`. Остальные маршруты (`/product/[id]`,
  `/cart`, `/checkout`, `/admin/*`) строятся с нуля и «пляшут от данных» —
  появляются сразу после своего функционала (см. этапы 3–5), а не как
  статичные заглушки на этом этапе.

### Этап 2: База данных и сервисы

Спроектировать Drizzle-схему:

- `users` (id, email, passwordHash, role, provider, tokenVersion)
- `products` (id, name, slug, description, price, composition, weight,
  calories, allergens, shelfLife, image, isAvailable, category)
- `orders` (id, userId nullable, guestId, email, phone, address, comment,
  status, total, paymentId, invoiceUrl)
- `order_items` (id, orderId, productId, quantity, priceAtTime)

Открытые вопросы схемы (решаются при реализации):

- Нужен ли `passwordHash` при passwordless-аутентификации.
- Журнал платежей/вебхуков для идемпотентности (отдельная таблица).
- Enum статусов заказа.

Дальше по этапу:

- Накатить миграции.
- Написать сервисный слой (`shared/services/`):
  - product-service — чтение каталога, товара, обновление полей;
  - cart-service — Redis (чтение, добавление, удаление, очистка);
  - order-service — создание заказа, изменение статуса;
  - payment-service — создание платежа, обработка вебхука;
  - invoice-service — PDF, R2, письма.

### Этап 3: Каталог и корзина

Функционал и его страница делаются сразу вместе (страница пляшет от данных
соответствующего сервиса):

- Страница каталога — SSR (данные из product-service) + работающие фильтры,
  сортировка, пагинация.
- Страница товара — SSR (данные из product-service).
- Корзина — Redis, через Server Actions; страница корзины — из cart-service.
- Страница оформления — форма для гостя (email, телефон, адрес).
- Создание заказа — без проверки остатков, без резервов.

### Этап 4: Платёжный поток и уведомления

- Server Action — создание платежа в ЮKassa, редирект на оплату.
- Вебхук — подтверждение оплаты, смена статуса заказа
  (**идемпотентность** обязательна).
- Генерация PDF — после оплаты, сохранение в R2 (приватно, signed URL).
- Письма — админу (заказ с данными), пользователю (подтверждение +
  ссылка на PDF).
- QStash — фоновые задачи (PDF, письма).

### Этап 5: Аутентификация и админка

- Auth.js — VK ID, Яндекс ID, магическая ссылка.
- Гостевой чекаут — основной сценарий.
- Предложение создать аккаунт — после оплаты.
- Привязка корзины при логине — переключение ключа в Redis.
- Админка:
  - `/admin/products` — CRUD товаров (с загрузкой картинок в Vercel Blob);
  - `/admin/orders` — список заказов, просмотр, изменение статусов.
- Защита — только роль admin (+ решить, как выдаётся первая роль admin).

### Этап 6: AI-friendly и публичное API

- JSON-LD на странице товара (Schema.org).
- `sitemap.xml` + `robots.txt`.
- Публичные роуты:
  - `/api/public/catalog` — список товаров;
  - `/api/public/product/[id]` — один товар.
- Rate limiting — через Upstash Redis (как в kurstata).

### Этап 7: Полировка и деплой

- Мета-теги, Open Graph (+ opengraph-image), favicon'ы.
- Оптимизация картинок (next/image).
- Проверка всех писем и PDF.
- Деплой на Vercel — автоматически при пуше.
- Документация для пользователя (кто получит админку).

## Открытые вопросы вне этапов

- Фискализация (54-ФЗ): чеки через решение ЮKassa или осознанно отложить.
- Мониторинг ошибок (Sentry / Vercel Logs).
- Стратегия бэкапов Turso.
