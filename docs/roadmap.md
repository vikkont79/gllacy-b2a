# Roadmap — Магазин мороженого «Глейси»

## Цель

Учебно-боевой проект, который становится реальным инструментом продажи мороженого собственного производства. Производство под заказ — без остатков и резервов.

**Покупатель:** витрина → страница товара → корзина → заказ без регистрации → оплата → подтверждение.
**Владелец:** уведомление о заказе → обработка в админке (статусы, PDF-накладная).

## Принципы

1. **Простота** — гостевая покупка в один клик.
2. **Гибкость** — производство под заказ.
3. **Расширяемость** — новый тип товара = клон проекта с новой БД.
4. **b2a** — структурированные данные для поисковых агентов; сквозная тема, применяется в каждой вертикали.
5. **Передаваемость** — админка понятна человеку без технического бэкграунда.

## Сквозные темы

Применяются внутри каждой вертикали, а не «этапом после всего».

### b2a / структурированные данные
- Стабильные slug-URL у товаров (фундамент заложен в схеме)
- JSON-LD `Product` (вертикаль 2)
- `sitemap.xml` + `robots.txt` — когда URL стабильны
- Публичный API: `/api/public/catalog`, `/api/public/product/[slug]` + rate limiting
- Внятные `metadata` (title/description) на каждой странице
- `llms.txt` — карта для LLM-агентов; экспериментально, когда контент стабилизируется, не обязательный стандарт

Принцип: берём всё, что может быть полезно агентам, пока это не стоит существенной сложности. Рендеринг (ISR/SSR) — решение для людей и серверов, b2a — отдельный слой данных (JSON-LD, API, семантика), их не смешиваем.

### Рендеринг и кеш
Решение принимается в момент каждой вертикали, без догм:
- **Главная** — ISR
- **Каталог с фильтрами** — SSR через `searchParams`
- **Персональные данные** (корзина, профиль) — SSR
- Кешировать только при замеренной выгоде: запросы к Turso копеечные, избыточный кеш — сложность без пользы

### Безопасность
- Rate limiting на публичных роутах (Upstash)
- Идемпотентность платёжных вебхуков
- Секреты только на сервере, httpOnly-куки
